# TASK ARCHIVE: Detect Windows Terminal's active colorScheme

## SUMMARY

Windows Terminal schemes named by `profiles.defaults.colorScheme` or the default profile are flagged `active`, so Mirror can treat one as in use. After PR 13 review, a `{ dark, light }` `colorScheme` object flags both names and does not inherit defaults, and scheme-name matching is case-insensitive.

## REQUIREMENTS

- Flag the scheme named by `profiles.defaults.colorScheme` or the default profile (`defaultProfile` GUID).
- Fixture test in the existing parser harness.
- Per-profile schemes beyond the default profile stay out of scope.
- Review: do not treat `{ dark, light }` as unset; do not inherit defaults when `colorScheme` is present but not a string; compare scheme names case-insensitively.

## IMPLEMENTATION

Ghostty-style split: `activeWindowsTerminalScheme` in `src/parsers/iterm2.ts` returns `string[]` from one shared JSONC parse (`parseWindowsTerminalSettings`). Default-profile `colorScheme` wins over defaults. GUID compare is case-insensitive; a legacy `profiles` array is supported. `discoverWindowsTerminal` sets `active` via `isWindowsTerminalSchemeActive` (case-fold). Docs: `README.md`, `memory-bank/systemPatterns.md`.

Key files: `src/parsers/iterm2.ts`, `src/discover.ts`, `test/parsers.test.ts`, `test/fixtures/windows-terminal-settings.json`.

## TESTING

TDD in `test/parsers.test.ts`. First pass 19/19 then 23/23 after review fixes. `npm run compile` succeeded. `/niko-qa` PASS. No discover filesystem tests (issue #5).

## LESSONS LEARNED

- A stub that returns `undefined` or `[]` greens absence tests before any real code; only positive-path tests enforce TDD red.
- House style is a sibling active helper sharing one parse, not a combined `{ schemes, activeName }` return.
- Windows Terminal `colorScheme` may be a string or `{ dark, light }`; names match case-insensitively.
